# Употреба

## Брзи старт

Ако желите брзо да креирате конкретну пријаву:

1. [Подесите податке (config) ↗](#конфигурација-config) — jednom pri prvom pokretanju
2. [Преузмите најновије податке (fetch) ↗](#преузимање-података-fetch)
3. [Креирајте извештај (report) ↗](#генерисање-пореског-извештаја-report)
4. Отпремите креирани XML на портал **еПорези** (секција ППДГ-3Р)

За аутоматско добијање свих пријава и праћење њихових статуса —
користите [sync](#синхронизација-података-и-креирање-пријава-sync) уместо корака 2–3.

## Конфигурација (config)

```bash
ibkr-porez config
```

Креирање или измена личних података и подешавања приступа IBKR-у.

Биће вам затражено:

*   **IBKR Flex Token**: [Преузимање токена ↗](ibkr.md#flex-web-service)
*   **IBKR Query ID**: [Креирање Flex Query-а ↗](ibkr.md#flex-query)
*   **Personal ID**: ЈМБГ / ЕБС
*   **Full Name**: Име и Презиме
*   **Address**: Адреса пребивалишта
*   **City Code**: Троцифрени код општине. Пример: `223` (Нови Сад). Код можете наћи у [шифарнику](https://www.apml.gov.rs/uploads/useruploads/Documents/1533_1_pravilnik-javni_prihodi_prilog-3.pdf) (видети колону "Шифра"). Такође доступан у падајућем менију на порталу еПорези.
*   **Phone**: Телефон
*   **Email**: Email
*   **Data Directory**: Апсолутна путања до фолдера са фајловима података (`transactions.json`, `declarations.json`, `rates.json`, итд.). Подразумевано: `ibkr-porez-data` у фолдеру апликације.
*   **Output Folder**: Апсолутна путања до фолдера за чување фајлова из команди `sync`, `export`, `export-flex`, `report`. Подразумевано: фолдер Downloads вашег система.

## Преузимање података (fetch)

```bash
ibkr-porez fetch
```

Преузима најновије податке са IBKR и синхронизује курсеве са НБС (Народна банка Србије).

Чува их у локално складиште.

## Увоз историјских података (import)

```bash
ibkr-porez import /path/to/activity_statement.csv
```

Учитавање историје трансакција старије од 365 дана, која се не може преузети путем Flex Query-а (`fetch`).

Да бисте креирали фајл са трансакцијама на порталу Interactive Brokers погледајте [Извоз пуне историје ↗](ibkr.md#извоз-пуне-историје-за-import-команду)

> ⚠️ Не заборавите да покренете `fetch` након `import` како би апликација додала максимум детаља бар за последњу годину
> у мање детаљне податке учитане из CSV-а.

### Логика синхронизације (import + fetch)

При учитавању података из CSV-а (`import`) и Flex Query-а (`fetch`), систем даје приоритет потпунијим Flex Query подацима:

*   Подаци Flex Query-а (`fetch`) су извор истине. Они преписују CSV податке за било које подударне датуме.
*   Ако се запис Flex Query-а семантички поклапа са CSV записом (Датум, Тикер, Цена, Количина), то се рачуна као ажурирање (замена званичним ID-ем).
*   Ако се структура података разликује (нпр. сплит налози у Flex Query-у против "спојеног" записа у CSV-у), стари CSV запис се уклања, а нови Flex Query записи се додају.
*   Потпуно идентични записи се прескачу.

## Синхронизација података и креирање пријава (sync)

```bash
ibkr-porez sync
```

Ради све исто што и [fetch](#преузимање-података-fetch):

*   Преузима најновије трансакције са IBKR путем Flex Query-а
*   Синхронизује курсеве валута са НБС

Након тога креира све потребне пријаве за последњих 45 дана (ако већ нису креиране).

Приход који стигне у апликацију са закашњењем — после неуспеле везе, због курса који недостаје или просто зато што га је IBKR пријавио неколико дана касније — биће обухваћен следећим `sync`-ом док је његов датум још унутар тих 45 дана. Не постоји ознака „синхронизовано до овог дана”, па закаснели подаци никада не бивају прескочени.

Старији приход апликација не пријављује на сопствену иницијативу: рок за подношење је прошао, па је подношење ваша одлука. Затражите га изричито, проширивањем прозора:

```bash
# пријави непријављен приход последњих 400 дана
ibkr-porez sync --lookback 400
```

> 💡 Ако веза са IBKR-ом не успе, `sync` и даље креира пријаве из већ локално сачуваних трансакција и исписује упозорење; команда се завршава успешно, а у GUI-ју се поновни покушаји за свежим подацима настављају аутоматски у следећем циклусу.

Затим можете [Управљати креираним пријавама](#управљање-пријавама).

> 💡 Ако сте покренули `sync` први пут и она је креирала пријаве које сте већ подали пре почетка коришћења апликације,
> можете брзо да их све означите као плаћене и уклоните из излаза [list](#списак-пријава-list):
> ```bash
> ibkr-porez list --status submitted -1 | ibkr-porez pay
> ```

### Синхронизација из преузетог XML фајла (`sync --file`)

Ако IBKR API привремено није доступан, можете ручно преузети Flex Query XML са IBKR сајта и користити га:

```bash
ibkr-porez sync --file /path/to/report.xml
```

Ради све исто што и `sync` — чува трансакције, креира све потребне пријаве — али чита податке из локалног фајла уместо позивања IBKR API-ја.

Погледајте [како преузети Flex Query XML ↗](ibkr.md#преузимање-flex-query-xml-а-за-sync---file).

У GUI-у, иста опција доступна је у менију **☰** као **Sync from Flex Query XML…**.

### Измењене пријаве

Порез плаћен у иностранству на једну расподелу није коначан. Након затварања године амерички фонд пријављује брокеру коначан порески карактер прошлогодишњих расподела, па брокер сторнира порез који је задржао — уобичајен случај је ETF на трезорске записе чија се расподела покаже као дивиденда каматног карактера — и задржава изнова ако нови карактер то налаже. То се дешава од неколико недеља до отприлике петнаест месеци након исплате.

Када се износи на којима почива већ креирана PP OPO пријава промене, следећи `sync` креира измењену пријаву. То је обична пријава у сваком погледу: појављује се у [list](#списак-пријава-list), добија сопствени XML у излазном фолдеру, подноси се и плаћа као свака друга. Испод линије о креираној пријави `sync` исписује датум остваривања прихода и број оригинала — оно по чему се оригинал проналази у табели ePorezi.

Измењену пријаву треба поднети: она замењује првобитну. Ако је број оригинала забележен преко [`submit --number`](#подношење-пријаве-submit), већ је у документу; у супротном га уписујете на ePorezi, проналазећи оригинал по датуму остваривања прихода.

Поређење се ради у валути прихода, па промењен курс никада не доводи до измењене пријаве. Такве промене `sync` тражи до 1. јануара претходне године, без обзира на прозор за креирање нових пријава.

## Генерисање пореског извештаја (report)

```bash
ibkr-porez report
```

Ако не наведете тип извештаја и период, подразумевано се генерише ППДГ-3Р за последње пуно полугодиште

* Креира `ppdg3r_XXXX_HY.xml` у [Output Folder](#конфигурација-config)
* Увезите овај фајл на портал Пореске управе Србије (еПорези)
* Ручно отпремите фајл из [Документ потврде](ibkr.md#документ-потврде) у Тачку 8

Да бисте изабрали други тип пријаве или временски период погледајте документацију

```bash
ibkr-porez report --help
```

### ПП ОПО за период (`report --type income`)

```bash
# приход текућег месеца до данас
ibkr-porez report --type income

# изричито задат период
ibkr-porez report --type income --start 2025-07-01 --end 2025-12-31
```

Уписује у излазни фолдер по један ПП ОПО XML за сваку групу прихода и не ради ништа више: пријава се при томе не евидентира, па се ти фајлови не појављују у [list](#списак-пријава-list), не пореде се са оним што је [sync](#синхронизација-података-и-креирање-пријава-sync) већ креирао и никада не доводе до измењених пријава. Пријаве које намеравате да водите креира `sync`.

Група за коју порез по одбитку још није стигао се не уписује. Уместо фајла команда исписује од ког датума ће бити пријављена: порез се обично књижи у року од неколико дана од прихода, а документ са признањем које брокер још није дорачунао вреди сачекати. Након тог датума група се уписује са нултим признањем и пуних 15% за уплату — управо то подносите ако порез никада не стигне.

`--force` то чекање не скраћује. Значи само „генериши са приближним подацима“: где Народна банка нема курс за датум, користи се најближи из кеша, а где недостају подаци о празницима за годину, рок доспећа се рачуна само по радним данима.

## Управљање пријавама

Након креирања пријава путем команде [sync](#синхронизација-података-и-креирање-пријава-sync) можете их прегледати, мењати статус и извозити за отпремање на порески портал.

### Списак пријава (list)

Приказује списак свих пријава са могућношћу филтрирања по статусу.

```bash
# Прикажи активне пријаве (подразумевано):
# draft + submitted + pending
ibkr-porez list

# Прикажи све пријаве
ibkr-porez list --all

# Филтер по статусу
ibkr-porez list --status draft
ibkr-porez list --status submitted
ibkr-porez list --status pending
ibkr-porez list --status finalized

# Само ID пријава (за коришћење у цевима)
ibkr-porez list --ids-only
ibkr-porez list --status draft -1
```

Пример коришћења у linux-стилу:

```bash
# Поднети све нацрте
ibkr-porez list --status draft -1 | ibkr-porez submit
```

### Преглед детаља пријаве (show)

Приказује детаљне информације о одређеној пријави.

```bash
ibkr-porez show <declaration_id>
```

Приказује:

*   Тип пријаве (ППДГ-3Р или ПП ОПО)
*   Период пријаве
*   Статус (нацрт, поднета, на чекању, завршена)
*   Детаље трансакција и прорачуна
*   За PPDG-3R: добитак/губитак признат од стране пореске управе поред
    израчунатих вредности, искоришћени пренос капиталних губитака (почетно/
    искоришћено/кориговано/крајње стање) и из којих "транши" је искоришћен
*   Приложене фајлове

### Подношење пријаве (submit)

```bash
ibkr-porez submit <id> [<id> ...]

# забележити број који је порески портал доделио пријави
ibkr-porez submit <id> --number 1234567890
```

Означава пријаву као поднету (увезену на порески портал).

Понашање зависи од типа пријаве:

*   `PPDG-3R` након `submit` прелази у статус `pending` (чека решење пореске управе о износу пореза).
*   `PP OPO` након `submit`:
    *   прелази у `submitted` ако постоји порез за плаћање;
    *   прелази директно у `finalized` ако је порез `0`.

`--number` бележи број пријаве на пореском порталу — од 1 до 19 цифара, за једну пријаву одједном. Ако пријава касније буде [измењена](#измењене-пријаве), измењена пријава носи тај број да би пореска знала коју пријаву замењује. Без њега се измењена пријава свеједно креира, а број уписујете на ePorezi.

У GUI-у, дугме **Submit** отвара дијалог потврде са истим опционим пољем.

### Плаћање пријаве (pay)

```bash
ibkr-porez pay <id> [<id> ...]
ibkr-porez pay <id> --tax 1234.56
```

Означава пријаву као завршену (`finalized`) и чува датум плаћања.

Опција `--tax` омогућава да одмах забележите износ пореза током плаћања, без посебног корака `assess`.

Након тога ће нестати са списка приказаног [list](#списак-пријава-list) (без `--all`)

### Евиденција износа по решењу пореске (assess)

```bash
# Забележи званичан износ пореза из решења
ibkr-porez assess <declaration_id> --tax 1234.56

# Забележи износ и одмах означи као већ плаћено
ibkr-porez assess <declaration_id> --tax 1234.56 --paid

# Забележи губитак признат од стране пореске управе (само за PPDG-3R)
ibkr-porez assess <declaration_id> --loss 50000.00 \
    --reference "RES-123/2025" --date 2025-09-01

# Забележи добитак признат од стране пореске управе (само за PPDG-3R)
ibkr-porez assess <declaration_id> --gain 12000.00
```

Команда је најважнија за `PPDG-3R`, где износ пореза, као и признати капитални
добитак/губитак, одређује пореска управа након подношења пријаве.

Шта команда ради:

*   уписује званичан износ пореза у метаподатке пријаве (`--tax`);
*   са `--paid` одмах пребацује пријаву у `finalized`;
*   без `--paid`:
    *   ако је износ већи од нуле, пријава остаје активна (`submitted`) за накнадно плаћање;
    *   ако је износ нула, пријава прелази у `finalized`.

Мора бити наведена бар једна од опција: `--tax`, `--gain`, `--loss`.

`--gain` и `--loss` су доступни само за `PPDG-3R` и уписују капитални
добитак/губитак признат од стране пореске управе — чувају се поред
израчунатих вредности апликације и могу се разликовати од њих (због CPI
корекција или методологије пореске управе). Једно решење не може истовремено
признати и добитак и губитак.

`--reference`, `--date` и `--notes` су подаци о решењу (број, датум,
напомене). Приказују се у [show](#преглед-детаља-пријаве-show), а за признати
губитак број и датум решења се додатно уписују у део 7 будућих PPDG-3R
пријава (види [пренос капиталних губитака](#пренос-капиталних-губитака-carryforward)),
па их вреди евидентирати.

Ако решење признаје губитак (`--loss` већи од нуле), креира се (или ажурира)
запис у регистру [преноса капиталних губитака](#пренос-капиталних-губитака-carryforward).
Пренос се увек заснива на губитку признатом од стране пореске управе, а не на
израчунатом.

> ⚠️ Након што је пренети губитак макар делимично искоришћен у једној од
> наредних пријава, признати губитак се више не може мењати путем `assess` —
> команда ће вратити грешку.

### Пренос капиталних губитака (carryforward)

```bash
ibkr-porez carryforward
```

Приказује листу свих "транши" (vintages) капиталних губитака признатих од
стране пореске управе, доступних за пренос у будуће периоде:

*   пријаву-извор и период за који је губитак признат;
*   признат и преостали (неискоришћени) износ;
*   пореску годину након које пренос истиче (губитак се може пренети највише
    5 година унапред);
*   статус: `Active` (може се користити), `Exhausted` (потпуно искоришћен),
    `Expired` (истекао рок).

Иста листа је доступна у GUI-ју у менију **☰** → **Capital loss carryforward...**.

Свака PPDG-3R пријава креирана путем
[sync](#синхронизација-података-и-креирање-пријава-sync) аутоматски умањује
израчунату пореску основицу користећи расположиве преносе (од старијих ка
новијим периодима), док се основица не сведе на нулу или се преноси не
исцрпе. Преглед [report](#генерисање-пореског-извештаја-report)-а приказује
искоришћени и преостали износ преноса након тога. Износ се одбија из регистра
само једном — приликом чувања пријаве; поновни `sync` за исти период га не
одбија поново.

Пренети губици се такође пријављују у самој пријави: у PPDG-3R XML-у се
попуњава део 7 („Капитални губици“) — по један ред за сваки активан пренос,
са бројем и датумом решења пореске управе (7.2/7.3) и преосталим износом
губитка (7.4). Коначни `Osnovica` и `PorezZaUplatu` у XML-у такође узимају у
обзир примењени пренос. Пријављивање губитка у делу 7 је обавеза самог
пореског обвезника — без тога га пореска управа неће применити у решењу.

Број и датум решења се узимају из
[assess](#евиденција-износа-по-решењу-пореске-assess) (`--reference` и
`--date`). Ако нису евидентирани, поља 7.2/7.3 у XML-у остају празна, а
`report` исписује упозорење — евидентирајте их кроз `assess` и поново
генеришите извештај, или попуните та поља ручно на порталу.

### Извоз пријаве (export)

```bash
ibkr-porez export <declaration_id>
ibkr-porez export <declaration_id> -o /path/to/output
```

Копира XML и све приложене фајлове ([attach](#приложавање-фајла-уз-пријаву-attach)) у [Output Folder](#конфигурација-config) или у каталог наведен у параметрима.

### Повратак статуса пријаве (revert)

```bash
# Вратити на нацрт (подразумевано)
ibkr-porez revert <id> [<id> ...]

# Вратити на поднету
ibkr-porez revert <id> [<id> ...] --to submitted
```

Враћа статус пријаве.

### Брисање пријаве (delete)

```bash
# Преглед плана (ништа се не мења)
ibkr-porez delete <id>

# Обриши пријаву
ibkr-porez delete <id> --yes

# Дозволи брисање пријаве која није нацрт
ibkr-porez delete <id> --yes --force
```

Брише пријаву и поништава њен утицај на књигу преноса: пренос губитка који је искористила враћа се изворним „траншама”, а њена сопствена транша признатог губитка (направљена преко `assess`) се уклања. Ако сте је обрисали да бисте исправили грешку, затим покрените `sync` да поново направите период из сачуваних трансакција — до PP OPO пријаве чији је датум прихода старији од 45 дана допире `sync --lookback N`.

Без `--yes` само исписује шта би било обрисано. `--force` је неопходан за брисање пријаве која није нацрт. Може се обрисати само најновији PPDG-3R — брисање старијег оставило би „висећи” пренос код каснијих пријава; PP OPO пријаве се могу брисати у било ком тренутку.

Тако се исправља и признати губитак претходне пријаве који је каснија већ искористила: обришите каснију пријаву (ослобађајући пренос), поново покрените `assess` на ранијој, па `sync` за поновно прављење.

У GUI-ју је иста радња доступна дугметом **Delete** у реду пријаве: отвара дијалог за потврду (уместо `--yes`) са пољем **Force** за пријаве које нису нацрт.

### Приложавање фајла уз пријаву (attach)

```bash
# Приложити фајл
ibkr-porez attach <declaration_id> /path/to/file.pdf

# Обрисати приложени фајл
ibkr-porez attach <declaration_id> <file_id> --delete
ibkr-porez attach <declaration_id> --delete --file-id <file_id>
```

Приложава фајл уз пријаву или уклања приложени фајл из складишта пријава.

За чување у складишту пријава користи се само име фајла (путања се одбацује), тако да имена морају
бити јединствена - иначе ће фајл са истим именом преписати раније учитан фајл са истим именом чак и из друге путање

> 💡 Приложени фајлови се копирају заједно са XML пријаве током [извоза (export)](#извоз-пријаве-export)

## Извоз Flex Query (export-flex)

```bash
ibkr-porez export-flex 2025-01-15
ibkr-porez export-flex 2025-01-15 -o /path/to/output.xml
ibkr-porez export-flex 2025-01-15 -o -  # Излаз у stdout (за цеви)
```

Извоз XML фајла Flex Query добијеног током [fetch](#преузимање-података-fetch) или [sync](#синхронизација-података-и-креирање-пријава-sync) на наведени датум.

Пример коришћења у linux-стилу:

```bash
ibkr-porez export-flex 2025-01-15 | ibkr-porez sync --file -
```
